## 決定

| 項目 | 決定 | 原因 |
|---|---|---|
| 給誰用 | 一個部署服務一個**商家**（公司或門店）；要服務第二個就再部署一套 | 多商家要處理帳號隔離、多個 webhook、AI 排隊分配，第一版不值得 |
| 測試商家 | 繼續用虛構的「森日茶屋」 | 題庫、案例庫、改進迴圈都能沿用 |
| 程式結構 | **Go 服務**（非 AI 模型的全部）＋**Vue Vben Admin** 後台＋**Swift 模型服務**（只包 Apple 本機模型）（[ADR 0001](adr/0001-go-service-with-vben-admin.md)） | Apple 模型只能從 Swift 呼叫；其餘集中在 Go，對話邏輯不跨兩種語言 |
| 模型 | **預設用 Apple 本機模型（AFM）**；可以切換成 Haiku，兩者走同一條路（2026-10-09 決定） | 本機免費、資料不出 Mac；Haiku 是選用的，量過題庫再看要不要切 |
| 回覆 | 分類（選擇題）→ 狀態機，或一般對話的混合式：先挑 FAQ（挑到回答案原文，其他語言翻譯後驗證），挑不到才「挑知識段落＋AI 寫回覆＋原文片段驗證」（[ADR 0002](adr/0002-ai-writes-replies-from-knowledge.md)，2026-10-09 修訂） | 本機模型挑 FAQ 照回 117/118、自由寫回覆只有 86/118；FAQ 沒寫到的才讓 AI 寫，原文片段讓程式能驗證 |
| 商家設定 | 存 SQLite、後台編輯；自由文字知識，沒有結構化欄位（[ADR 0003](adr/0003-merchant-config-in-admin.md)） | 給不懂技術的商家用；每家店規則差很多 |
| 語言 | 商家用慣用語言輸入，AI 依顧客語言回覆；固定回覆儲存時翻譯；顧客語言由商家勾選（預設中英日） | 商家不用寫三種語言 |
| 聊天平台 | Go 版第一版只接 Telegram，之後接 LINE（平台抽一層） | 同原計畫 |
| 員工端 | Telegram 員工群組（轉人工、預約確認／拒絕） | 同原計畫 |
| 後台對外 | 和 webhook 共用 Cloudflare Tunnel，用獨立網址，前面加 Cloudflare Access；後台自己也要帳號密碼登入 | 後台能改機器人說的每一句話 |
| Swift 版 | 停止開發，測試機等 Go 版 | Haiku、後台在 Swift 版做完都要丟掉 |
| 對話紀錄 | 連同 AI 判斷存 SQLite，90 天後自動刪除 | 同原計畫 |

## 架構

```
Telegram（之後 LINE）──webhook──> Cloudflare Tunnel ──> Go 服務（Mac）
                                                         │ 驗證 secret、依 update_id 去重、先回 200
                                                         ▼
                                              平台層：統一成「哪個平台、哪位顧客、說了什麼」
                                                         ▼
                                              分類意圖（選擇題，參考意圖案例庫的相似句子）
                                                         │
                       ┌─────────────────────────────────┼─────────────────────────────┐
                       ▼                                 ▼                             ▼
          預約、取消、轉人工、追問…           一般對話                            自訂意圖
          狀態機＋固定回覆                    挑 FAQ → 挑知識 → AI 寫回覆 → 驗證   固定文字／轉人工／指定知識
                       │                                 │ 沒過 → 轉人工、進待補問題
                       ▼                                 ▼
          回覆顧客／通知員工群組            SQLite：商家設定、知識、案例、顧客狀態、
                                            待處理、預約、對話紀錄、待補問題、AI 費用
                                                         ▲
                              後台 JSON API ── Vben Admin（獨立網址，Cloudflare Access）

模型層：Haiku（Go 直接呼叫）／Apple 本機模型（HTTP → Swift 模型服務，一次只跑一個）
語意向量：Go 內建多語言 embedding 模型（找相似的意圖案例，跨語言）
```

## 後台功能

| 項目 | 內容 |
|---|---|
| 商家資訊 | 名稱、介紹、聯絡方式必填；其餘是有標題的自由文字知識段落 |
| FAQ | 問題 → 答案，用慣用語言寫 |
| 意圖案例庫 | 內建案例只能看；商家新增自己的案例，意圖用白話顯示；不能和題庫重複 |
| 自訂意圖 | 最多 10 個，要說明和至少 3 句例句，動作選：回固定文字、轉人工（附提示）、只根據指定知識回答。儲存後自動用所有例句跑分類自我測試，顯示衝突 |
| 預約 | 開關；關閉時回固定回覆「預約關閉」（不轉人工）；欄位固定為日期、時間、人數、姓名、電話 |
| 轉人工 | 總開關（關閉時回固定回覆「轉人工關閉」，含聯絡方式）、用綁定碼綁定 Telegram 群組（後台可以重新產生綁定碼）、觸發條件（顧客要求固定開啟、找不到答案時轉、聲稱／無關累計次數）、員工服務時段、自動結束、提示文字（固定回覆「轉人工提示」） |
| 待補問題 | `answerable: false`、原文片段驗證沒過、分類為看不懂的訊息；相同問題合併計次；附翻成慣用語言的版本；可轉成 FAQ、知識段落、意圖案例，或忽略；員工回覆過的預填成答案 |
| 固定回覆 | 開放打招呼、預約關閉、轉人工提示、轉人工關閉、時段外提示；改慣用語言版本，儲存時翻成其他啟用語言，可逐語言修正 |
| 語言 | 慣用語言、顧客語言勾選（中英日以外的語言提示品質沒量過）；沒啟用的語言回「目前只支援…」並轉人工 |
| 模型 | Haiku／本機切換、每月費用上限（超過自動切回本機並通知員工群組）；API key 放環境變數，後台看不到 |
| 只能看 | 預約列表或日曆、對話紀錄（附 AI 判斷和擋下原因，按鈕翻譯）、本月 AI 費用和呼叫次數 |
| 介面 | 繁中、英、日；一種管理員角色；第一個帳號用指令建立 |

暫不做：反面案例庫、禁止主題、連續抱怨或重問同一題就轉人工。

## 開發順序

每一項開一個 GitLab issue，照順序做：

0. **技術驗證：Go 的多語言語意向量**：hugot（或同類）＋`multilingual-e5-small` 在 Apple Silicon 上能不能跑、要不要 cgo；把 Swift 版找相似案例的來源換成它，量分類題組有沒有變差。決定 Go 版用哪個 embedding。
1. **骨架**：`go/` 專案、SQLite（資料表照搬 Swift 版）、Telegram webhook（secret、去重、先回 200、正在輸入、重試）。
2. **模型層**：`ChatModel` 介面、Haiku（structured outputs）、Swift 模型服務、假模型；本機模型排隊；token 與費用記錄。
3. **分類＋狀態機**：11 個內建意圖（含「想找真人」）、意圖案例庫找相似句子、預約狀態機照搬（相對日期 #16、短答不切換語言 #17、與原文一致性檢查）。
4. **挑知識＋寫回覆＋原文片段驗證**。
5. **員工群組**：轉人工、員工回覆、結束轉人工、預約確認／拒絕、非文字訊息（照搬 #11、#13、#14）。
6. **後台 API＋Vben**：登入、商家資訊、FAQ、意圖案例、預約與轉人工設定、固定回覆與翻譯、語言、模型設定；介面多語言。
7. **待補問題**。
8. **自訂意圖＋分類自我測試**。
9. **只能看的頁面和費用**。
10. **題庫執行工具改接 Go**：`run_flows.py`、`loop/score.py` 改成呼叫 Go 服務；分類題組改成 11 類；新增誘答題和跨語言題；量 Haiku 和本機模型。

測試機部署（#12）和開放測試版（#15）排在 Go 版完成之後。

## 完成條件（開放測試版前）

- [ ] 題庫分數不低於 Swift 版（`swift-final`）；分類題組依 11 類重新標記後比較
- [ ] 誘答題的編造率量過，Haiku 和本機模型各一份
- [ ] 員工群組可以轉人工和回覆顧客
- [ ] 預約可以確認和拒絕
- [ ] 伺服器重開不會掉資料
- [ ] 後台可以完成森日茶屋的全部設定，不用改檔案

## 測試機部署

- 獨立的 Apple Silicon Mac。只用 Haiku 時不需要 Apple Intelligence；要用本機模型時才需要，並在啟動時檢查模型版本。
- 用 launchd 讓 Go 服務、Swift 模型服務和 cloudflared 開機自動啟動、當掉自動重啟。
- 每天備份 SQLite。

## 題庫和改進迴圈

- 題庫格式不變，改成對 Go 服務跑；`eval/` 的森日茶屋檔案當固定的測試資料，匯入成 Go 版的商家設定。
- 改進迴圈暫停，Go 版穩定、題庫能跑之後恢復；之後**只改提示詞和內建意圖案例**，不改程式。
- 測試版開放後，定期看對話紀錄和待補問題：答錯或轉人工的句子改寫、去掉個資後加進題庫；`python3 eval/check_overlap.py` 必須沒有重複。

## 之後
