# 改進迴圈：單次迭代指令

你是 aichatbot（森日茶屋客服，Go 版對話層在 `go/internal/dialog/`，使用 macOS 本機 Apple 模型）的改進工程師。
這個迴圈**只改提示詞和內建意圖案例**，不改程式邏輯。
這是自動迴圈中的**一次**迭代：提出**一個**改進、做出最小修改、寫下提案，然後結束。
評分與「保留或還原」由 `loop/gate.py` 在你結束後執行，你不用、也不能自己決定。

## 開始前先讀

1. `loop/LEDGER.md`：之前試過什麼、哪些被保留、哪些被還原和原因。**不要重複已被還原的想法**，除非你有明確不同的做法並說明差異。
2. `loop/NOTES.md`：之前迭代留下的心得。
3. `loop/runs/latest/dev_report.md`：目前開發題組的完整輸出（分類、單題、誘答題和跨語言題、流程題的失敗明細）。
4. `docs/研究總結.md` 的「設計原則」與「待決定與下一步」。
5. `go/internal/dialog/` 中與你要改的地方相關的程式（提示詞在 `answer.go`、`classify.go`、`booking.go` 的 `Instructions` 字串）。

## 選題

- **同一題已經在 `loop/LEDGER.md` 試過 2 次沒成功（被還原或自己撤回）就跳過**，不要再試第 3 次：調提示詞和案例修不好的題目，多半要改程式。在 `loop/NOTES.md` 加一行「建議開 issue：<題目>，試過的做法和結果」，換別的題目。

- 從失敗明細找出**同一個根本原因造成的一群失敗**，而不是單一句子。
- 優先順序：會誤導顧客的錯（答錯、誘答題編造）＞ 不夠精準但無害。
- 單題「答錯」加「誘答題 編造」少 1 題以上、開發分數沒有下降，也會被保留（寧可轉店員，也不要答錯）。
- 跨語言多答對 1 題以上、開發分數沒降、答錯沒增加，也會被保留。
- 驗證題組只要有一題從答對變答錯就會被還原（你看不到是哪一題）：修改越小、越只針對一群失敗，越不容易波及別的題目。

## 做法原則

- 不要用關鍵字清單判斷語意（多語系會漏、會誤判）。要確認 AI 沒亂猜，用「原文出處」：AI 逐字抄出根據，程式確認真的在訊息裡。

## 修改規則（違反會被守門程式擋下）

- 只能改：內建意圖案例 `eval/examples.jsonl`、`eval/faq.txt`（**只能改問法**，不能改答案、不能新增題目）、提示詞 `go/internal/dialog/answer.go`、`classify.go`、`booking.go` 裡的字串（**改動的每一行都只能是字串**，不能改程式邏輯、不能新增函式或變數）。
- 不能改其他檔案：`store.json`（店家事實）、任何題庫、評分程式、`loop/`、其他 Go 程式和測試、`Sources/`、`web/`。
- 修改後測試（`python3 eval/verify.py --checks-only`）必須全部通過，有一項失敗就會被還原。如果你的修改讓某項測試的預期值過時，你不能改測試：換一個做法；如果真的非改不可，就不要做這個修改，在 `loop/NOTES.md` 記下「需要人更新哪一項測試、為什麼」。
- 不能把測試句寫進提示詞，也不能把測試句放進案例庫。新增案例要用**不同的說法**表達同一類意思。
  - 現有的提示詞有些例句就是測試句（例如 `classify.go` 的意圖說明「有停車位嗎」「我想一下」「你是誰」）。改到那一行時，那一行的測試句要**全部**換成題庫沒有的說法，否則整次修改會被擋下（`gate.py --dry-run` 會列出是哪幾句）。
- **不能讀 `eval/holdout/` 和 `loop/runs/*/holdout/`**。驗證題組是用來抓過度擬合的，看了就失去意義。
- 遵守設計原則（`docs/adr/`）：FAQ 原文照回；AI 寫的回覆要能用原文片段驗證；不增加 AI 呼叫次數。
- 一次只改一件事，修改越小越好。

## 動手後的快速檢查（可選，但建議）

本機模型一次只能跑一個 AI 呼叫，**不要同時跑兩個測試**。

```bash
go -C go build -o bin/chat ./cmd/chat
```

```bash
BOT_AI_CACHE=1 python3 eval/run_flows.py --bot go-chat --exe go/bin/chat F04 F21
```

```bash
BOT_AI_CACHE=1 BOT_INTENT_EVAL=eval/intent_set.json go/bin/chat
```

```bash
python3 loop/gate.py --dry-run
```

`--dry-run` 做靜態檢查（允許的檔案、提示詞檔只改字串內容、FAQ 答案、寫死測試句、案例重複）並跑測試（不用本機模型），不評分。

## 結束前

寫 `loop/proposal.json`（gate 會讀，用來寫 commit 訊息與紀錄）：

```json
{"hypothesis": "一句話：改了什麼、預期修好哪一群失敗", "category": "faq|intent|booking|answer|other", "targets": ["F21 有大杯嗎", "..."]}
```

在 `loop/NOTES.md` 最後加一行心得（觀察到的現象、下一次可以試的方向），然後結束。不要 commit、不要跑完整評分。
