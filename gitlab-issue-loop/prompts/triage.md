判斷規則：
- **need_info**：只在有「無法自行決定」的疑問時才用：
  - 沒有合理的預設做法，需要人類提供資訊（帳號、店家資料、商業規則、外部系統的設定）；或
  - 選錯了很難改回來（資料會遺失、資料庫結構無法回復、對外公開的行為、安全與權限）。
  `comment` 寫成要貼到 issue 的回覆：先用一兩句說你對需求的理解，再用編號列出具體問題，每題盡量附上你建議的選項，讓人類可以只回「1 選 A」。只列無法自行決定的疑問；其他疑問照下面 ready 的方式自己決定。不要問讀程式碼就能自己找到答案的問題。
- **ready**：可以直接動手。疑問都已經解答（包括先前留言中你問過、人類已回覆的），或剩下的疑問都有合理的建議做法、之後也改得回來。
  後者不要停下來問，直接照你建議的做法進行：在 `comment` 裡用「我自行決定的事項」列出每一項（選了什麼、為什麼，一項一句），人類看到不同意可以在 MR 審閱時推翻。
  `comment` 寫成「開始處理」的回覆，簡述你要怎麼做與如何驗證（有自行決定的事項就附上）；`plan` 寫給開發階段的你看的詳細計畫（要改的檔案、步驟、要新增的測試，以及自行決定的事項）。
  如果 issue 的描述或專案文件和實際狀態不一致（例如寫著「等 #3」但 #3 已關閉），以程式碼和 issue 狀態為準，在 comment 裡註明。
